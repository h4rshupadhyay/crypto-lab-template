**SECURE CORPORATE EXPENSE REPORTING SYSTEM**

**Scenario**

A company accepts expense reports from employees in three departments: **Engineering, Marketing, and Finance**.

The system must protect individual expense amounts, detect tampering, authenticate employees, and calculate department-wise expense totals without revealing individual amounts to the processing server. Authorized officers must also be able to search reports by department or expense category.

**Requirements**

**Client side**

An authenticated employee enters:

- Report ID
    
- Department ID
    
- Expense category: Travel, Equipment, or Training
    
- A positive whole-number expense amount in rupees
    
- A short description that does not contain the amount
    

The client performs the following operations:

1. Encrypts the expense amount using the **Paillier public key** belonging to the Finance Authority.
    
2. Creates a record containing the report ID, employee ID, department ID, category, description, and **Paillier-encrypted amount**. The plaintext amount must not appear in this record.
    
3. Computes a **SHA-256 hash** of the serialized record.
    
4. Encrypts the record using **AES-128 in CBC mode**, with suitable padding and a fresh session key and IV.
    
5. Encrypts the AES session key using the processing server’s **RSA-2048 public key**, with OAEP padding.
    
6. Generates a **Schnorr digital signature** over a consistently serialized submission package containing the report ID, encrypted AES key, IV, AES ciphertext, and record hash.
    
7. Obtains a signed timestamp token from a simulated trusted timestamp authority. The token must bind the submission time to the hash of the signed package.
    

Display the record hash, IV, AES ciphertext, wrapped session key, Schnorr signature, Paillier ciphertext, and submission timestamp.

**Server side**

The processing server must:

1. Verify the timestamp authority’s signature and confirm that the token belongs to the submitted package.
    
2. Check whether the submission occurred within the configured expense-reporting period.
    
3. Verify the employee’s Schnorr signature using their registered public key.
    
4. Decrypt the AES session key using its RSA private key.
    
5. Decrypt the record and recompute its SHA-256 hash.
    
6. Compare the recomputed hash with the submitted hash and validate the employee identity and report ID.
    
7. Accept valid reports and reject altered, duplicate, or late submissions.
    
8. Retain each expense amount in its **Paillier-encrypted form**.
    
9. Maintain a **symmetric searchable encryption index** supporting exact searches by department and category. Searches should return report IDs without decrypting report contents. Use secret-key-derived search tokens; do not use an unkeyed hash of the search term.
    
10. Homomorphically aggregate the encrypted amounts of accepted reports belonging to a selected department.
    

Each report must contribute only once to a department aggregate.

**Finance Authority**

The Finance Authority must:

1. Authenticate before accessing its menu.
    
2. Select a department aggregate generated by the server.
    
3. Decrypt only that aggregate using the Paillier private key.
    
4. Display the department ID, number of included reports, and total expense amount.
    

The processing server must not possess the Paillier private key. The application must not provide an individual-expense decryption option.

**Task**

Write a **menu-driven Python program** implementing the specified client, server, and Finance Authority functions.

Enforce role-based access using authenticated accounts. Selecting a role from the main menu alone must not grant access.

Use suitable data structures, files, or a database to store encrypted records, signatures, hashes, timestamp tokens, verification status, and searchable indexes. Keep private keys separate from stored submission records.

For this exercise, the client, server, and timestamp authority may be simulated using separate functions or classes within one program. Socket programming is not required.
